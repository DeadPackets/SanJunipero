## Global Constraints

Every task's requirements implicitly include this section.

- **G1. Determinism.** Randomness is drawn ONLY at event-emission time, by a named `RngStreams` stream, and the result is recorded in the payload. `fold()` stays pure and RNG-free. New streams this chunk: `illness`, `fauna`, `regrowth`, `forage`, `worldgen`. Existing reused: `combat`, `fire`, `health`, `wildlife`, `reproduction`, `mystery`.
- **G2. Hash stability by absence.** Every new `WorldState` field is **optional and absent until first written** (the C9 `pairNights` / `laws` pattern). `genesisState()` must not create `fauna`, `forageables` or `traffic`. Consequence: the **G1 golden `f487a26b…` must never move in this chunk.** A task that moves it STOPS and reports.
- **G3. One golden regen.** `GOLDEN_G2_HASH` moves exactly once, in **Task 37**. Until then `G2_CONFIG` in `packages/engine/src/g2.test.ts` pins every C11 `enabled` flag to `false` (Task 2 writes those pins; Task 37 removes them all). Any task that moves G2 while pinned STOPS and reports.
- **G4. One place per derived constant.** Any constant derived from config is computed in exactly ONE exported function and imported everywhere else — the `DEFAULT_RECENT_WINDOW_TICKS = ceil(boredomTicks × 1.1) = 132` bridge-deafness lesson. Named derivations this chunk: `dayPhaseFromTick`, `terrainCostFor`, `fertilityAt`, `lightLevelAt`, `visionRadiusAt`, `chunkOf`, `thirstDecayPerTick`. **No task may inline a second copy of any of them.**
- **G5. Four-seam config derivation.** `fold`, `submitIntent`, `composePerception` and `hears` each call `effectiveConfig(base, state.laws)` themselves. **Any new entry point into physics must do the same or it silently ignores world laws.** New seams this chunk: the construct recognizer's effective-config read (ops-side), `lightLevelAt`/`visionRadiusAt` callers, and every new system function (systems get it free through `ctx.config`, which is a getter — do not cache it).
- **G6. Schema discipline.** Zod 4; new object schemas `.strict()`; **new fields on existing event payloads are `.optional()`** so recorded logs keep parsing. `SimConfigSchema` is touched by **exactly one task (Task 2)** — a later task that wants a dial adds it to Task 2's list and re-runs Task 2, it does not touch the schema itself. This is what keeps `stateHash(DEFAULT_CONFIG)` moving once, not twenty times.
- **G7. World laws.** Every new config section carries an `enabled` flag defaulting `true`; every flag and every starred dial from addendum §11/§19 is whitelisted in `TOGGLABLE_PATHS` with its value schema. Flips travel only as `config_changed` at a tick boundary.
- **G8. One-way glass.** Construct types, milestone kinds, concept taxonomy and tier labels never enter a prompt, a perception packet, or an agent memory. Asserted mechanically by the banned-vocabulary scan (Task 33) over prompt assembly across the whole G11a suite.
- **G9. Naming law.** The recognizer names a *type*; a **name** comes only from an agent's own utterance or inscription, stored verbatim with `{eventSeq, quote, byId}` provenance. No coined name → `name: null`, and viewer copy says so ("a gathering not yet named").
- **G10. No mechanics in world text.** Chronicle labels, perception prose, refusal strings and narrator vocabulary are human-framed. Banned in any world-facing string: `hp`, `severity`, `affliction`, `config`, `tier`, `roll`, numbers-as-stats. Existing `FORBIDDEN_FRAMING` applies unchanged.
- **G11. §21 is closed, not pending.** **No atomic paired `trade` verb, ever.** Exchange stays `give` + speech. A task that "fixes" this is rejected.
- **G12. Tier-1 registry alarm.** `TIER1` in `packages/engine/src/verbs.test.ts` asserts `Object.keys(VERBS).sort()` both ways. Every new Tier-1 verb (`drink`, `fill`, `dig_channel`, `douse`, `pave`, `hunt`, `wear`, `doff`, `kindle`, `snuff`, `stoke`) must be added to that array in its own task or the suite goes red. That is the intended alarm.
- **G13. Cost discipline.** Live-API work happens only in Tasks 39 (G11b) and, budget-capped, Task 35's detector. Hard USD cap enforced by the C9 BudgetGuard + `checkSpend`; `semanticFirsts.dailyBudgetUsd` default `0.10` skips the pass with an ops alert on cap, never silently.

## Phase B — the body: mortality, illness, poison, care

### Task 5: Afflictions on the body, and the drain that is pure arithmetic

**Files:** Create `packages/engine/src/systems/mortality.ts`, `packages/engine/src/systems/mortality.test.ts`; Modify `packages/engine/src/state.ts`, `packages/engine/src/events.def.ts`, `packages/engine/src/fold.ts`, `packages/engine/src/worldTick.ts`, `packages/engine/src/perception.ts`.

**Interfaces — Produces:**
- `AfflictionKind = 'injury' | 'poison' | 'illness' | 'fatigue'`; `AgentBody.afflictions?: Array<{kind: AfflictionKind; severity: number; sinceTick: number}>` — **absent until the first affliction** (G2).
- Events: `agent_harmed {agentId, amount, source: 'attack'|'fire'|'accident', byId?}` (fold: `hp -= amount`, clamped at 0); `agent_afflicted {agentId, kind, severity, sourceId?, itemId?}` (fold: add, or **merge** by summing severity onto an existing affliction of the same kind and keeping the earlier `sinceTick`); `affliction_worsened {agentId, kind, severity}` (fold: set severity); `affliction_recovered {agentId, kind}` (fold: remove; removing the last one **deletes the field**, restoring the absent shape).
- `mortalitySystem(ctx)`: per tick, per living agent, sorted by id — `drain = Σ over afflictions of mortality.drainPerTick[kind] × severity`, plus `mortality.hungerHpDrainPerTick` when `needs.hunger <= 0`, plus `mortality.thirstHpDrainPerTick` when `thirst <= 0` (Task 11). Emits one `hp_changed {agentId, delta: -drain}` when `drain > 0`. **Zero RNG.**
