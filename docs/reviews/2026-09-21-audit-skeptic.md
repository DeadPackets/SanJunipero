# Skeptical review of the architecture audit

2026-09-21. Independently checked the world, Forge/operations, medium/engagement and Jev reports against current source and primary documentation. Two pure local reproductions used fabricated data and an in-memory database. No runtime edits, production changes or paid calls.

## Verdict

The clearest defects are evidence attribution and delivery/control boundaries. The reports do not establish that navigation, physics breadth, model price or the simulation engine is the principal cause of poor viewing. Retain the engine and existing plan executor while testing the specific missing contracts. A semantic decision layer is an experiment, not a demonstrated architectural rescue.

The classifier's category itself remains outside the mind prompt.

## Challenged or narrowed

| Claim or proposed direction | Correction / missing tradeoff |
|---|---|
| Conversation means a complete physical action lock | False as a blanket statement. `coordinator.#standStill` stops only walking and explicitly leaves work alone. `agentRuntime.ts:755–758` submits pending intents and pumps existing plans before checking scene wake reasons. The actual gap is that scene answers cannot author new physical intentions and ordinary deliberation is gated. Existing work/plans can continue. The minds report has been narrowed accordingly. |
| Repeated pair scenes prove failed promises | Not from the current sample. The inspected promises concern supper while observation was still before supper. Nineteen actual Bashir item/room actions occurred between ticks 598 and 718. Repetition is real, but a missed deadline or complete inactivity is not established. The two-oldest-ties selection is a stronger causal finding. |
| The town lacks semantic decisions over deterministic execution | Much already exists: named-parameter interpretation and walk/exit-first chaining in `engine/intent.ts:54–98,139–171`, moving-target pursuit, and the runtime plan pump. A new place/activity graph could duplicate these responsibilities and introduce stale state. First specify the absent operation, such as a durable mind-authored commitment and its next action. |
| Give residents stable interests and memory access | These are existing foundations, not missing basics. The experiment should exercise current identity/personality/wants and retrieval, then show where they fail to change decisions. | Current hunger decay is 0.005 | This is the library default cited in world/medium reports. The production snapshot's effective law was 0.01. Daytime sleep threshold, energy decay and poison chance also differ from defaults. Use the effective-state table in the minds report for this run. |
| More humor and fewer speech prohibitions will improve engagement | Plausible, unmeasured. The existing rules also explicitly prohibit repeated counting and allow topic changes, plans and jokes; the sampled pair repeated counting despite those instructions. | A roofed alehouse is a functioning pub | The report correctly limits this, but the verdict can overpromise if quoted alone. The code supplies recipe, roof, room, storage, transfers and conversation. Service, consumable invented drinks, transactions and social adoption are separate. Existing `give` already permits real voluntary transfers; do not call commerce wholly absent or build a business framework merely to stage a pub. |
| Fixed low-level survival/navigation errors are current evidence | Old starvation, doorway, plot/resume and shutdown reports document earlier states. Current code contains body safeguards, room-aware speech, construction guidance, SIGTERM/reflection fixes and checkpoint recovery. Retain old reports as hypotheses/regressions, not current incident counts. |

## Jev and the proposed hybrid

The capability description is sound: the official [System One documentation](https://docs.typesafe.ai/concepts/system-one) describes typed decisions rather than generated prose. The [models page](https://docs.typesafe.ai/models) confirms $0.042 per million input tokens, free output and the stated context limits on the review date. The arithmetic in the Jev report is correct. None of this measures end-to-end savings or behavior in this town.

The missing tradeoff is the cost of creating the answer set. If an LLM must propose all options first, Jev adds another dependency and may not remove a paid turn. If code supplies options, it limits what residents can consider. “Other/reconsider” helps but does not prove that opportunities omitted by the shortlist will be noticed. Compare with the existing deterministic wake predicates and plan pump before adding inference to continuation.

The vendor's [documented limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13) are relevant to exactly this use case: indirect intent, large irrelevant state, time comparison and adversarial content can be unreliable. A resident's quoted demand must stay data, not controller instructions. Precompute time, legality and reach in code; pass only knowledge available to that resident. Revalidate after the response, as another resident may move or take the item while it is in flight.

[Project Sid](https://arxiv.org/html/2411.00114v1), sections 1.3 and 2.2, supports concern about conflicting speech/actions. It also explicitly notes that producing talking and action in one LLM call is a simple coherence solution before discussing many-output systems. San Junipero has twelve residents and modest outputs, not independent limbs/gaze/motor modules. The paper is not evidence that copying its ten-module architecture, adding a cognitive controller, or splitting every current turn is necessary here.

Strong first pilot: an observer-side relevance classifier or shadow-only reconsideration judgment against saved states. Weak first pilot: replace the resident's whole brain with a candidate selector. The first can measure calibration and regional latency without changing autonomy. The second confounds model substitution, option generation, memory and behavior at once. Neither is approved implementation merely because its price is lower.

## Unresolved; evidence needed before claiming an answer

1. Dominant source of uninteresting viewing → measure understandable scene coverage and missed utterances on the same recorded run, alongside actual idle, work and conversation time.
2. Commitment reliability → trace authored intention, remembered reminder, chosen plan, interruption and completion across a full day. Separate a changed mind from forgotten context or impossible physics.
3. Need for a place graph → count failed/repeated navigation attempts and their lost time; compare with existing semantic targets and chains. No current navigation bottleneck was established by these reports.
4. Long-term culture → verify co-presence, participant-specific knowledge and actual shared usage over several days before displaying tradition or authority as fact.
5. Operational hard cap → combine turn, narrator and art reservations in one fake near-cap run; test cancellation, reconciliation and store lifetime. Cross-store crash consistency remains an injection-test hypothesis, not proven corruption.

Recommended sequence: repair independently reproduced defects and viewer continuity, observe one complete current day, then compare a single narrow hybrid addition with the existing executor. The research supports these questions and controls; it does not establish Twitch retention or guarantee autonomous drama.

## Continuity follow-up: independently verified

| Finding | Precise state and evidence |
|---|---|
| Goals lose continuity at reflection | `reflection.ts:221` passes only today's scene summaries to `summarizeDay`; `:238` replaces `current.goals` with returned `standing`, including an empty list. The prior goal list is not an input. `PersonalityStore.updateCurrent:129–141` updates the latest version in place, so the previous active list is not guaranteed to have its own archived version. Source memories or an older personality version may still preserve the intention. This is active-state replacement, not deletion of all historical evidence. |
| Fact and summary stores are not retrieved | Repository-wide non-test call-site search finds no runtime reader of `factsAbout` or `summaryNodes`; `memory/retrieve.ts` searches memories, FTS, vectors and tags. These derived rows remain on disk. Do not claim reflection is wholly wasted: the newly generated day summary feeds autobiography and personality in the same run, and ledgers, autobiography, journal and memory gists do reach normal prompts. |
| Settlement is broader than a particular promise | `TieStore.apply:77–79` matches holder, other person and kind, not tie id/text; one settlement closes every open matching row. Rows remain stored with `settled_tick`; their history is not deleted. |
| Expiry can falsely imply a broken future promise | `TieStore.letGo:117–124` closes every non-kin tie seven days after its original tick, without due time or completion evidence. Restating a tie inserts another row rather than refreshing the old row's clock. Runtime emits `tie_let_go`; shared/gateway mappings turn expired promises into `promise_broken`, label them “a promise broken,” and apply the negative bond weight. Future-due promises cannot be distinguished structurally. |
| Prompt age is stale while body age advances | Runtime stores initial `spec.identity`; `#withHands:1836` refreshes skills only. `assemble.ts:107` renders `identity.age`. The engine increments `ageDays` at day boundaries; 28 simulation days equal a year. This is prompt/body disagreement, not an aging-system failure. Resolve-cast rebuilds identities from founding/birth/arrival facts rather than current body age. |

Additional privacy qualification: current conversation turns scrub other people's asides through `threadFor`; that reviewed path is safe. However, `sceneLlm.closeMessage:368–378` includes every private aside in the closing request. `coordinator.#close:750–778` broadcasts its generated summary and saves the same summary for cast and overhearers. The prompt asks for what was said, but there is no structural separation preventing an aside-derived fact entering shared memory. This is a verified exposure path and an unproven generated leak; add a mocked hidden-aside closure check before declaring scene privacy complete.
