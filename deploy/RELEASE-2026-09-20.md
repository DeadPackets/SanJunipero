## Before launch

1. Use the verified source and image together. Set `SJ_RELEASE_IMAGE`, `SJ_TOWN_DATA_VOLUME`, `PORT=8090`, and the approved positive spending limits in the deployment environment. Load secrets from the existing protected environment file. Never print resolved Compose configuration.
2. Inventory the selected volume. A new production world must start with blank resident and narrator databases, but the prior production `_ops.db` must be retained with its SQLite sidecars. Do not copy a rehearsal town into production or combine independent rehearsal ledgers by overwriting one with another. Identify the authoritative production ledger before launch.
3. Configure the existing Litestream backup profile with the owner's bucket. Confirm a restore into a separate directory before opening the town. A same-server copy is useful recovery evidence but is not an off-server backup.
4. Validate Compose with `config --quiet`, and check that port 8090 is unused. Test the public reverse proxy, WebSocket upgrade and admin authentication after private startup.
5. Obtain the owner's deployment approval. Launch exactly one town process. Never run a scripted preview on the new production volume before the minds-on launch.

## Watch and rollback

- The container health probe checks HTTP and tick progress. After 15 minutes on one tick it fails, and Compose marks the container unhealthy after three failed probes. An intentional operator pause also triggers this condition. Investigate it rather than automatically restarting a paused town. `restart: unless-stopped` does not restart an unhealthy running container.
- Check the operations view for spend, failed calls, held minds and queued work. Check logs and memory, then inspect a conversation and a room in the viewer.
- Stop the town with a 20-second grace before taking a whole-directory recovery copy. Include world, narrator, every mind, and `_ops.db`. Restore the entire set into separate storage and run integrity checks before resuming it.
- To roll back viewer/runtime code, stop the candidate and select the previous verified image against the preserved data only if schemas remain compatible. Do not reset the world or its spending ledger. If data restoration is needed, use the full matched backup set.
- Do not delete any older volume until its identity and the desired retention have been reviewed. Never use `docker compose down -v` for a code rollback.
